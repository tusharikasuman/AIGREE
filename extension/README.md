# AIGREE browser extension (Phase 2)

Manifest V3 extension (React + TypeScript, built with [WXT](https://wxt.dev)).

**Cookie banners:** when a page shows a cookie popup, the toolbar icon gets an orange `!` badge. Open the popup and pick:

- **Necessary only**: rejects everything except the strictly necessary cookies that a site is allowed to set without consent. (Necessary cookies can't be refused, so this is the same as "Reject all".)
- **Accept all**

You can remember the choice per site, or set a default ("Automatically choose Necessary only") for every site. Banner detection and clicking use DuckDuckGo's [autoconsent](https://github.com/duckduckgo/autoconsent) rules (MPL-2.0), which cover over a thousand cookie-banner providers.

**Terms & trust score:** click **Check this site's terms** in the popup. The extension finds the page's Terms (or Privacy) link and sends it to the AIGREE backend. It then shows the grade and score, the worst issues with what you can do about them, and any good signs. Results are saved per site. The backend must be running: by default the extension uses `http://localhost:8000`, and you can change this under **AIGREE server** at the bottom of the popup.

## Develop

```powershell
cd extension
npm install        # also prepares the cookie rules (see below)
npm run dev        # opens a Chrome window with the extension loaded and reloads on save
npm run build      # production build in .output/chrome-mv3
npm run zip        # .zip for the Chrome Web Store
```

## Load the build in your own Chrome / Edge

1. `npm run build`
2. Go to `chrome://extensions` (or `edge://extensions`) and turn on **Developer mode**
3. Click **Load unpacked** and pick `extension/.output/chrome-mv3`

After changing code, run `npm run build` again and click ↻ on the AIGREE card in `chrome://extensions`. To see errors, click **service worker** on that card.

## Layout

```
entrypoints/
  content.ts      # runs autoconsent in every page/frame; finds the Terms link
  background.ts   # banner status per tab (badge), site-specific cookie rules, autoconsent's page snippets, terms analysis
  popup/          # React popup: cookie buttons, per-site memory, defaults, trust score, server setting
utils/
  settings.ts     # stored settings + per-tab status types
  analysis.ts     # trust-score types shared with the backend
  rules/          # generated by scripts/split-rules.mjs (git-ignored)
scripts/split-rules.mjs
```

### Why the cookie rules are split

autoconsent has about 1,400 rules, and more than half of them each apply to a single site. Bundling them all would put 1.1 MB into every page and frame. `scripts/split-rules.mjs` runs before every install, dev and build:

- The **generic** rules go into the content script.
- The **site-specific** rules stay in the background worker, which sends each frame only the rules that match its URL.

This halves the content script to about 580 KB. autoconsent's own compact rule format would be smaller still, but it drops the opt-in steps, so **Accept all** would stop working.
